# Security Policy

## Supported versions

This project is pre-1.0. Only the latest tagged release and the `main` branch receive security fixes.

| Version        | Supported |
| -------------- | --------- |
| latest release | yes       |
| `main`         | yes (development) |
| older releases | no — upgrade first, then re-check |

Fixes are released as new patch or minor versions; published tags are never moved or deleted.

## Reporting a vulnerability

**Do not open a public issue for a security vulnerability.**

Use GitHub's private vulnerability reporting instead:

1. Go to the repository's **Security** tab.
2. Select **Report a vulnerability** (under "Private vulnerability reporting").

If private reporting is unavailable, contact the maintainer through a private GitHub channel (@cberane) rather than a public issue or PR.

- You will get an acknowledgment within **72 hours**.
- Please allow coordinated disclosure: do not publish details until the fix has been released.
- Fixes are shipped as a new release and credited in the changelog if you wish.

## Scope

What this project is: a zero-dependency Node CLI and a POSIX shell script that copy skill files into a project, plus the markdown skill and templates those files contain. Reports are in scope when they affect:

- **`bin/ai-project-starter.js` and `install.sh`** — writing outside the target directory, overwriting unrelated files, mishandling of symlinks or path traversal, unsafe handling of an existing skill directory.
- **Skill and template content** (`skills/setup-project/`) — anything shipped by this repo that could execute code in, corrupt, or inject instructions into a user's project or AI-agent session.
- **CI workflows** (`.github/workflows/`) — command injection or unsafe processing of untrusted input in the pipeline.
- **Supply chain** — anything that lets code run under the project's name from a source other than the repository owner's intent.

Out of scope:

- Vulnerabilities in a **project generated by the skill** — the generated files live in your repository and are yours to maintain. Report them to that project.
- Vulnerabilities in the **coding harness itself** (Claude Code, vibe, and others) — report those to the harness vendor.
- Social engineering, denial of service, or missing hardening with no concrete exploit path.
- Vulnerabilities that only reproduce on an **unsupported version** — first upgrade to the latest release.

## Supply-chain notes

- The installer has **zero npm dependencies** (Node stdlib only), so there is no transitive dependency tree to audit.
- `install.sh` downloads from this repository only and falls back to `main` if a tag cannot be fetched.
- Prefer pinned installs in automation: `npx github:cberane/ai-project-starter#vX.Y.Z`.

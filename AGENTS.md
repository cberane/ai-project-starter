# AGENTS.md — ai-project-starter

This file is the **single source of truth** for every AI agent working in this repository. Read it fully before acting.

## Project identity

- **Name:** ai-project-starter
- **Type:** CLI tool + agent skill
- **What it does:** a portable `/setup-project` skill that turns any fresh or existing repo into a configured, AI-assisted, spec-driven project through a one-question-at-a-time interview, plus the npx installer that delivers the skill.

## Language rule

All output — code, comments, commit messages, PR descriptions, documentation, and conversation — is **English only**, even if the user prompts in another language.

## Git rules

- **No AI attribution, ever.** Do not add `Co-Authored-By:` trailers, "Generated with …", "Made with AI", or any similar attribution to commit messages or PR descriptions. Commit messages must read as if written by the user alone.
- **Commit style:** conventional commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`).
- **Never modify git configuration.** Do not run `git config` write commands and never set or change identity or signing settings. If identity is missing, inform the user.
- Only commit or push when the user asks.

## Architecture rules (do not break these)

1. **One canonical copy of the skill** lives in `skills/setup-project/`. Never create mirrors, copies, or sync scripts for it. Dogfooding uses the installer with `--user`.
2. **The installer is dumb, the skill is smart.** `bin/ai-project-starter.js` only copies files — no templating, no interviewing, no dependencies (Node stdlib only).
3. **`AGENTS.md` is the single source of truth** in projects generated by the skill; generated harness wrappers stay thin.
4. **Harness support is data, not logic.** New harnesses (Codex, OpenCode) = new rows in the harness tables in `skills/setup-project/SKILL.md` and the installer's `HARNESS_DIRS` — plus docs. Do not restructure the flow.
5. **Templates use `{{tokens}}` and `<!-- IF:condition -->` blocks.** Every token and condition must be declared in `skills/setup-project/references/tokens.md`. Never leave a token or marker that could survive rendering.

## Versioning and releases

This project follows **semantic versioning** (`major.minor.patch`). Three version locations must always match:

1. `package.json` → `version`
2. `skills/setup-project/references/VERSION`
3. the git tag `v{version}`

What counts as what (while pre-1.0, i.e. `0.x.y`):

- **patch** (`0.1.x` → `0.1.x+1`): bug fixes, docs, CI, internal refactors — no change to the installer's flags or the skill's interview flow, question catalog, or generated output
- **minor** (`0.x.0` → `0.x+1.0`): new features (new flag, new interview question, new template or role) and any breaking change — breaking changes must be called out in the changelog entry
- **major**: reserved for the 1.0 release and beyond

Rules for every change set:

1. **Fill `CHANGELOG.md` while you work** — add entries under `[Unreleased]` (Added / Changed / Fixed). Never leave notable changes unrecorded.
2. **Increase the version as necessary** per the table above, in `package.json` and `references/VERSION` together, in the same change.
3. **Fix the installer pin in `README.md` and `docs/INSTALL.md`** — the `npx github:cberane/ai-project-starter#v{version}` example must always show the latest released tag.
4. **Release procedure**: move `[Unreleased]` to `## [v{version}] - YYYY-MM-DD` in the changelog → commit → push to GitHub → tag the pushed commit `v{version}` → create the GitHub release from that tag. The tag must always match the pin shown in `README.md`.
5. **Never move or delete a published tag.** If a release turns out broken, fix forward with a new patch release.

## Workflow

Direct mode: one task at a time, spec-driven via `specs/` (SPEC → PLAN → TASK). Verify before finishing: `node --check`, `bash -n`, and a smoke test of the installer in a scratch directory for any installer change.

## Verification checklist (before any commit)

- `node --check bin/ai-project-starter.js`
- `bash -n install.sh`
- Installer smoke test in a scratch dir (install, rerun for no-op, upgrade path)
- No attribution strings anywhere: `grep -riE 'co-authored-by|generated with' .` returns nothing
- English only in all changed files
- Version locations in sync: `package.json` == `references/VERSION` == latest tag; `README.md` and `docs/INSTALL.md` pins show the latest tag
